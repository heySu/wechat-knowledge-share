知识小站 · Agent 学习笔记 07

前六期拉直成一张图：七个阶段、三个判断、一张体检表。约 1600 字，读完 5 分钟，也是整个系列的目录。

01 / 地图

七个阶段，一张图

前六期是一条链子，今天把它拉直，画成一张图：

跑通 → 跑对 → 跑久 → 跑得起 → 敢上线 → 改得动
 01     02     03      04        05        06

每个阶段的典型症状和该做的事：

  • 跑通：它能聊，但不会自己动手。→ 加工具、加循环。
  • 跑对：会动手了，但常选错工具、编参数。→ 改描述、上 schema。
  • 跑久：一中断就失忆。→ 上 checkpoint。
  • 跑得起：能跑，但账单吓人。→ 缓存、砍步数、分级。
  • 敢上线：能跑，但不敢交给用户。→ 权限、审计、灰度。
  • 改得动：上线了，但每次改都心虚。→ 建评测集。

顺序不用死守，但跳级几乎都会返工。最常见的是从「跑通」直接跳到「敢上线」——中间四段的债，会在上线第一周全部到期。

02 / 判断

先说什么时候「不该」用 Agent

这一节可能比前面六期都值钱。

Agent 适合这样的任务：目标清楚、路径不清、结果可验。 三个条件缺一个，就该退回去。

  • 路径是确定的：别用 Agent，用 workflow 或者一段脚本。让模型在二十个固定步骤里「自由发挥」，只会带来不确定性，不会带来智能。
  • 只做一步：一次 prompt 就够了。加循环只是给一次调用套了个壳，成本翻倍，效果不变。
  • 结果没人能验：最危险。没有判定标准的任务，Agent 只会把混乱放大——它做得越多，你越不知道该信哪一段。

一句话总结：Agent 的价值在「路径不确定」这件事上；路径越确定，它越像负债。

03 / 三个「什么时候」

加工具、加循环、以及停手

什么时候加工具？ 当它需要外部事实，或者需要改变外部状态时。查数据库、读文件、发请求、写入——这些它自己做不到。

不需要就别加。工具越多，路由越难，第 02 期那三种翻车就越容易发生。一个能用的 Agent，工具数往往比你以为的少。

什么时候加循环？ 当步骤数不确定，而且下一步依赖上一步的结果时。

步骤固定，就别循环；一次能并行拿到的，就别串行。循环是给「需要看结果再决定」的任务准备的，不是默认配置。

什么时候停手？ 三个信号，出现任何一个就该停：

  • 失败一次的代价，已经超过人工做一遍的成本。
  • 工具加到第五个，它开始频繁选错。
  • 你说不清它为什么成功。

最后一个是最强的信号。靠运气跑通的东西，你没法维护，也没法改进——你只能祈祷。祈祷不是工程。

04 / 体检表

五道题，定位你在哪一段

每题 0-2 分：0 = 完全没有，1 = 有但不稳，2 = 有且可信。

  1. 你能用一句话说清它交付什么吗？（目标）
  2. 它失败时，你能在五分钟内还原现场吗？（审计）
  3. 中断之后，它能接着跑吗？（状态）
  4. 你知道它跑一次花多少钱吗？（成本）
  5. 你能证明这次改动没让它变差吗？（评测）

总分 0-10：

  • 0-3 分：还在 demo。先别谈上线，先把第 1、2 题做到 2 分。
  • 4-7 分：能内测。补最弱的那一项，通常第 5 题最缺。
  • 8-10 分：可以交付。这时候的瓶颈往往不在 Agent，在流程和值班。

这张表有个好处：它不评价模型，只评价你的工程。换模型能救的分数很少，剩下的大多要靠上面六期那些事。

05 / 收尾

这七期，可以怎么用

三种用法，按投入排：

  • 自查：拿体检表给自己手上的 Agent 打分，找到最弱的一项，回对应的那一期。
  • 评审：第 05 期那十个问题 + 这张体检表，正好是一次上线评审的议程。
  • 带人：地图讲结构，前六期讲细节。新人从 01 开始读，比丢一本框架文档有效。

七期的完整目录：

01 结构    模型 + 工具 + 记忆 + 循环
02 失败    三种翻车与三道防线
03 续跑    对话是流水账，状态是账本
04 成本    平方量级与三处优化
05 上线    权限、审计、灰度
06 评测    任务集、判定、回归
07 地图    什么时候用，什么时候停

写这个系列的初衷很简单：Agent 这个话题里，最缺的不是「怎么让它更聪明」，而是「怎么让它靠得住」。

聪明是模型的进步，靠得住是工程的积累。前者会一直发生，后者只能自己一点点补。

这个系列到这里结束。下一季想聊点更细的东西——具体到某类任务的实现拆解，比如客服、报表、代码审查，每种一类，带完整的 trace 和踩坑记录。

今日三句话

  1. 目标清楚、路径不清、结果可验——三条都满足才值得上 Agent，缺一条就退回 workflow。
  2. 最强的停止信号是「你说不清它为什么成功」；靠运气的成功没法维护。
  3. 七个阶段里最贵的成本，从来不是模型，是你不确定它在干什么。
